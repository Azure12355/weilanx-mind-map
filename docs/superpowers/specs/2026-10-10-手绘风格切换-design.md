# Weilanx Mind Map · 手绘风格切换

日期：2026-10-10
状态：已实现

## 目标

在「标准」和「手绘」两种风格之间切换。手绘风格 1:1 模仿 Excalidraw：rough.js 的抖动线条、斜线填充、Excalifont / 小赖手写字体。风格与配色主题互相独立，任意主题都能叠加手绘。

## 文件格式

- `MindDoc` 新增可选字段 `look`：`"hand"` 表示手绘，不写或 `"standard"` 表示标准。老文件不受影响。
- 同步修改：`src/core/types.ts`、`schema/wmind.schema.json`、`skills/weilanx-mind-map/references/format.md`、CLI（`wm` 能读取和设置 look）。
- 在画布上切换风格走 `setDocProp`，进入撤销历史，并把文件标记为已修改。

## 绘制

- **rough.js**：唯一新增的运行时依赖（约 9KB gzip），是 Excalidraw 本身使用的库。参数照搬 Excalidraw 默认值：roughness 1（「艺术家」档）、bowing 1、`fillStyle: "hachure"`、`hachureGap = strokeWidth × 4`、`fillWeight = strokeWidth / 2`，描边画两遍。不对外提供潦草度档位。
- **稳定性**：每个元素的 seed 由它的 id 哈希得到：节点用 topic id，分支线用子节点 id，关系线、外框、概要用各自的 id。所以拖拽、重绘、缩放时线条形状保持不变，只有尺寸变化才会重新生成。
- **缓存**：生成结果以 `(kind, seed, 几何参数, 样式)` 为 key 缓存，平移和缩放大导图时不重新计算。
- **输出**：用 `rough.generator()` 生成 path 数据，渲染成普通 SVG `<path>`，不直接操作 DOM，React 渲染方式和导出流程都不需要改。

### 覆盖范围

| 元素 | 手绘处理 |
|---|---|
| 节点形状（矩形、圆角、胶囊、椭圆） | 抖动描边；有底色的节点改成分支色斜线填充 |
| 下划线形状 | 抖动线段 |
| 分支连线（曲线、直线、折线） | 抖动线 |
| 根节点锥形粗线 | 改成加粗的手绘曲线（rough 无法画填充式锥形） |
| 关系线和箭头 | 抖动曲线 + 手绘箭头；虚线关系线保留 dash |
| 外框 | 抖动虚线框，标签底色保持实心 |
| 概要括号 | 抖动括号 |
| 选中框、折叠按钮、框选区域、拖拽影子、搜索高亮 | 不变（`.wm-ui` 界面元素） |
| 标记图标（优先级、进度、旗帜等） | 不变，保证小尺寸下可读 |

### 填充与文字色

- 手绘模式下，`fill` 不是 `none` 的节点一律改成斜线填充，描边用 border 色；没有 border 时用原 fill 色描边（线宽 2）。
- 与画布底色反差大的 fill（饱和色、深色）改用同色系浅色排线（`tint()`：Excalidraw 调色板查表，其余颜色与底色混合），和 Excalidraw 默认的浅色背景一致，避免斜线压字。
- 斜线填充的节点上，白字看不清，所以把原本解析为 `auto` 的文字色改为主题文字色（亮色主题 `#1e1e1e`）。用户在节点 style 里显式设置的 `textColor` 优先。
- 合并逻辑放在 `src/core/theme.ts` 的样式解析里，以 `look` 为参数，渲染层只拿最终样式。

## 字体

- 内置 **Excalifont**（拉丁字符，约 30KB woff2）和 **小赖 Xiaolai**（中文，按 GB2312 常用字裁成子集，约 1.5–2MB woff2）。两者都是 OFL 授权，许可证文件随包发布。生僻字退回系统字体。
- 小赖子集按 unicode-range 切成若干分片（参照 Excalidraw 的做法），浏览器只加载用到的分片。
- 手绘模式下所有主题的字体都换成 `Excalifont, Xiaolai, <原字体栈>`，标准模式不变。
- 排版测量依赖字体：先用 `document.fonts.load` 加载用到的分片，再测量，测量缓存 key 带上字体，避免先按回退字体排版再跳动一次。
- **导出**：导出的 SVG 只把用到的字符所在的分片以 base64 写进 `@font-face`。PNG 由这份 SVG 光栅化；SVG 图片内嵌字体在 `decode()` 之后才异步就绪，所以先预画一次、等 400ms 再正式绘制。
- **打包**：VS Code 和预览端由 Vite 作为资源打包（`new URL(..., import.meta.url)`，在 webview 里解析为资源 URI）；Obsidian 端用 esbuild 的 `dataurl` loader 内联。实测 vsix 1.9MB，Obsidian main.js 2.8MB。
- 字体由 `scripts/build-fonts.py` 从 `@excalidraw/excalidraw` 包生成：Excalifont 7 个分片原样保留，小赖 209 个分片裁到 GB2312（6763 个汉字全覆盖）后剩 38 个、1.69MB。许可证在 `webview/public/LICENSE-OFL.txt`，随构建产物发布。

## 主题

- `sketch` 主题改造为「Excalidraw」配色，id 保持 `sketch`，老文件兼容：
  - 亮色：白底 `#ffffff`，文字和描边 `#1e1e1e`；
  - 暗色：底色 `#121212`，文字浅色；
  - 分支色使用 Excalidraw 调色板（红 `#e03131`、绿 `#2f9e44`、蓝 `#1971c2`、橙 `#f08c00`、紫、青；实现时以 excalidraw 源码 `colors.ts` 核对色值）；
  - 去掉写死的 `HAND` 字体栈，字体由风格开关决定。
- 「Excalidraw 主题 + 手绘」就是 1:1 原味；其他主题加上手绘，保留各自的配色。

## 入口

- 在工具栏设置菜单和格式面板的主题区，主题网格上方各加一个「标准 | 手绘」分段切换，只读时禁用。
- 主题缩略图 `ThemeSwatch` 跟着当前风格变化，切到手绘时缩略图也用手绘线条。
- 补充中英文案（`webview/src/i18n.ts`）。

## 后续补充（2026-10-10）

- **填充样式**：文档级 `fillStyle`（默认 `hachure`）+ 节点 `style.fillStyle` 覆盖，取值 `hachure` `cross-hatch` `solid` `dots` `dashed` `zigzag` `none`，只在手绘画法下生效。`none` 只描边（保留原底色作描边色）；`solid` 保留原底色，文字按底色自动黑白；其余稀疏填充用浅色排线、文字用主题文字色。入口：「画布」页的默认填充样式（手绘时显示）和「样式」页的填充样式（手绘时显示），图标用 rough.js 实际绘制。
- **内容对齐**：节点 `style.textAlign`（`left` `center` `right`，默认居中），标签行与「标记 + 文字 + 图标」行一起对齐，编辑框同步。两种画法都生效。
- **修正**：手绘节点下面先铺一层画布底色，避免中心主题连出的线从斜线空隙里透出来。

## 不在本次范围

- 大纲视图的字体
- Markdown 导出（与风格无关）
- 潦草度档位（建筑师 / 漫画家）

## 测试

- 单元测试：`look` 字段的读写和校验；手绘模式下的样式解析（填充、文字色、字体）；CLI 设置 look。
- 视觉验收：用 playwright-cli 启动无头浏览器打开预览页，分别截图「标准 / 手绘 × 各主题 × 亮 / 暗」，与 Excalidraw 中同类图形的截图对照；拖拽节点后检查线条不抖动；检查导出的 PNG 和 SVG 带手绘字体。
- 性能：在 300 个节点左右的导图上平移和缩放，确认没有明显掉帧。
